#### Prompt Manager

The Multi-Agent framework connects the current agent/human with other agents/humans, which fundamentally involves **state transition** and **information transmission**. The state transition process is completed through the EKG graph inference, and will not be further elaborated here; **information transmission** is the process of storing, transmitting, and transforming all agent/human inputs/outputs into the language model input, i.e., Memory + Prompt Engineer.

In essence, the collaboration among agents is encapsulated in the sequence << receive information -> **convert to prompt** -> request LLM -> produce output -> **parse output** -> execute action >>. The charm of large language models lies in our ability to freely assemble known information (memory) to construct diverse natural language expressions that request desired answers from LLMs. However, due to the diversity of natural language expressions, writing prompts can be highly personalized. This may lead to the need to write a new prompt and parsing module each time we implement an agent SOP chain.

So, is it possible to reuse historical prompts? In the Crewai framework’s approach, multiple keywords such as system, role, task, context, and memory are set up to ease the developer's burden when writing prompts. However, this can inadvertently constrain the prompt framework, making it hard for developers to modify it as needed.

This provides a better management concept for the evolution of the Prompt Manager module in muAgent. It allows for the fragmented management of prompt frameworks, enabling the free assembly of fragmentary prompts in different conditions without rewriting their assembly logic.

For example, in this function call prompt, a simple multi-tier prompt structure is built using several keywords, allowing developers to write within this established framework.

1. AGENT PROFILE: Role Outline
   1. ROLE: Basic role settings
   2. AGENT INFORMATION: Information related to the associated agent
   3. TOOL INFORMATION: Information related to the associated tools
2. CONTEXT FORMAT: Contextual information
   1. SESSION RECORDS: Conversation records
   2. CURRENT QUERY: Current question
3. INPUT FORMAT: Input information
4. RESPONSE OUTPUT FORMAT: Output information

Regardless of the prompt template being used, it will ultimately consist of fragmented prompts. For example, `ROLE`, `AGENT INFORMATION`, and `TOOL INFORMATION` can be reused by other agents.

Next, I will discuss the fragmentation management process within the muAgent Prompt Manager module:

Since prompts are actually presented in a hierarchical data structure similar to a tree (with the actual implementation using a directed acyclic graph), we can use Title configuration to register nodes and register edges to initialize the complete prompt, while setting descriptions for each title or constructing them via functions; these functions or descriptions can also be reused multiple times without having to rewrite them for each new agent.

Prompt Engineering and the output parsing of language models are highly interconnected processes, so the necessary parser methods must also be implemented directly within the prompt manager class.

Ultimately, within the Prompt Manager module of muAgent, we can support the following functions:

- Support for free switching between various languages prompts
- Customization of Prompt Title hierarchy
- Support for custom Prompt functions
- Ability to pre-print prompts to clarify outputs and accelerate debugging
- Encapsulation of markdown-style prompt templates

#### Agent

The Agent module, based on the new model, prompt manager, and memory manager, modifies the previous four types of agent modes (SingleAgent, ReactAgent, TaskAgent, GroupAgent) and introduces two new modes: FunctioncallAgent and UserAgent, enabling more complex scenario adaptations.

It also optimizes the process of quickly initializing the environment configuration for agents, as exemplified below:

```python
# Model configuration
MODEL_CONFIGS = {
    "dashscope_chat": {
        "model_type": "dashscope_chat",
        "model_name": "qwen2.5-72b-instruct" ,
        "api_key": "sk-xxx",
    },
    "qwen_text_embedding": {
        "model_type": "dashscope_text_embedding",
        "model_name": "text-embedding-v3",
        "api_key": "sk-xx",
    },
}
os.environ["MODEL_CONFIGS"] = json.dumps(MODEL_CONFIGS)

# Agent configuration
tools = ["KSigmaDetector", "MetricsQuery"]
AGENT_CONFIGS = {
    "codefuse_simpler": {
        "agent_type": "SingleAgent",
        "agent_name": "codefuse_simpler",
        "tools": tools,
        "llm_config_name": "dashscope_chat"
    }
}
os.environ["AGENT_CONFIGS"] = json.dumps(AGENT_CONFIGS)

# Configuration initialization
project_config = get_project_config_from_env()
agent = BaseAgent.init_from_project_config(
    "codefuse_simpler", project_config
)

# Quick Q&A
query_content = "Help me check whether there was an anomaly with the server at 127.0.0.1 at 10 o'clock."
query = Message(
    role_name="human",
    role_type="user",
    input_text=query_content,
)
# base_agent.pre_print(query)

print("### input ###\n", output_message.input_text)
print("### content ###\n", output_message.content)
print("### step content ###\n", output_message.step_content)

#### EKG

<div align=center>
  <img src="https://mdn.alipayobjects.com/huamei_bvbxju/afts/img/A*l7OQSLUYPH8AAAAAAAAAAAAADlHYAQ/original" alt="Image" style="width: 800px; height:auto;">

EKG is a tri-party application that includes front-end, back-end, and algorithm services, which coordinates the initialization of the necessary basic environment required for the EKG service, while integrating multiple functional services. It aims to manage complex workflow SOPs, including agents, tools, and event graphs, ultimately supporting the state transitions and information transmission processes required in the Multi-Agent framework.

1. **State Transition**
   1. Nodes: Various types of nodes perform different functions.
   2. Edges (Node Interactions): The core graph reasoning and LLM determine the node execution mechanism, supporting concurrent, serial, branching executions, and more.
2. **Information Transmission**
   1. Message Passing (Memory): Abstracted to 8 discussion modes, simultaneously meeting information isolation requirements in different scenarios, including public inquiry, public notification, private inquiry, private notification, sequential speaking, simultaneous speaking, free discussion, and private discussion.
   2. Prompt Engineering: Defined various prompt templates depending on the node description.

In muAgent v2.1, the absence of a readily available Python SDK hindered developers’ ability to use muAgent for secondary development conveniently. Thus, in muAgent v2.1, the `EKG` class was introduced, which provides external interface capabilities through the Python SDK: Supports recording and editing nodes and edges, supports graph reasoning and generalization, and allows for the writing and development of various complex applications.

Details of muAgent v2.0: [Easily Build an AI Version of "Who's the Undercover" Game: muAgent Framework Turns Knowledge Graph into Orchestration Engine, Supporting Complex Reasoning + Online Collaboration](https://mp.weixin.qq.com/s/di_joj2NInGAGNqjDIsleA)

        "model_name": "qwen2.5-72b-instruct",
        "api_key": "sk-xxx",
    },
    "qwen_text_embedding": {
        "model_type": "dashscope_text_embedding",

        "api_key": "sk-xx",
    },
}

# Fill in agent configuration
AGENT_CONFIGS = {
    "codefuse_function_caller": {
        "config_name": "codefuse_function_caller",
        "agent_type": "FunctioncallAgent",
        "agent_name": "codefuse_function_caller",
        "llm_config_name": "qwen_chat"
    }
}
os.environ["AGENT_CONFIGS"] = json.dumps(AGENT_CONFIGS)

# Initialize configuration
from muagent import get_ekg_project_config_from_env

# Initialize EKG
from muagent import EKG
ekg = EKG(project_config=project_config, initialize_space=False)

# Add nodes and edges
ekg.add_node(node)
ekg.add_edge(start_id, end_id)

# Start graph reasoning
response = ekg.run("xxx")
```
